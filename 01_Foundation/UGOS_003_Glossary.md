# UGOS_003: System Terminology & Glossary

## 1. PURPOSE

This specification defines the canonical vocabulary for UGOS v1.0 to eliminate ambiguity across design documents, schemas, and implementation code.

---

## 2. CANONICAL DEFINITIONS

| Term | Category | Definition |

|---|---|---|

| **Engine** | System Architecture | A specialized core subsystem responsible for a single foundational domain (e.g., Reasoning, Planning, Intent, Tool Execution). |

| **Agent** | Execution Layer | An operational entity with a defined persona, capability parameter set, tool access boundary, and instruction contract. |

| **Tool** | Action Layer | An external function, API, script, or executable capability integrated into UGOS with strict permission boundaries. |

| **Workflow** | Process Layer | A reusable, deterministic sequence of steps (DAG) designed to execute complex operations with fallback paths. |

| **Task** | Lifecycle | A discreet unit of work requested by a user or generated by an engine, tracked via a unique `TaskID` through state transitions. |

| **State** | Lifecycle | The explicit, audited condition of a task within the finite state machine (`RECEIVED`, `PLANNING`, `EXECUTING`, etc.). |

| **Working Memory** | Memory System | Ephemeral storage holding current task context, intermediate agent outputs, and step results. |

| **Session Memory** | Memory System | Short-term context storage persisting across an active user conversation thread. |

| **Project Memory** | Memory System | Persistent context tied to a designated long-term project workspace. |

| **User Memory** | Memory System | User-controlled persistent preferences, constraints, and custom configuration profiles. |

| **Orchestrator** | Control System | The central execution engine managing state transitions, agent assignment, task DAG execution, and timeouts. |

| **Plugin** | Extension | An external adapter package extending UGOS tool, memory, model, or workflow capabilities via standardized SDK interfaces. |
